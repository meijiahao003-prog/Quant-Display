# 投资专家圆桌 · 个人本地原型

## 2026-10-21：接入观市看盘与三个专家 Skill

本版沿用原来的 **三专家＋主持人、ChatGPT 登录、Codex 本地运行**。无需填写模型 API Key。新增的「观市看盘接入」读取观市导出的同一批冻结价格、资金分时和来源时间，使用以下固定三席会审，并把本次结果回显到发起它的观市页面：

| 会审角色 | 实际加载的附件 | 限定职责 |
| --- | --- | --- |
| 宏观环境 | `dalio-druckenmiller-market.zip`（v1） | 政策、信用、预期与传导条件 |
| A 股盘面与波段 | `a-share-market-skill-v2.zip`（v2） | 价格、成交资金、市场结构、触发与失效条件 |
| 林奇基本面 | `lynch-thinking.zip` | 商业模式、盈利质量、估值与投资理由反证 |

`dalio-druckenmiller-kb-v2.zip` 作为参考知识库，默认仅加载其中 **15 条标记为正文已核验的投资方法摘要**。这表示包内资料分级，不表示本程序独立核验了原文；旧记录和未核验正文不进入默认研究。两份看盘 Skill 共享部分方法与来源，分别存放避免同名文件覆盖，主持人不把重复依据算成两次独立确认。

这次加载的是 **Skill 文本与资料摘要，没有训练或蒸馏模型权重**。只有指数或 ETF 行情时，林奇席须保留企业基本面证据缺口；历史宏观观点也不会被当成当前市场事实。

使用方式：

1. 启动本地圆桌，在原「模型与连接」中完成 ChatGPT 登录与真实连接验证。
2. 在观市选择标的，点击「送入投资 Agent」。打开的本地窗口会展示冻结标的、时间、来源、价格与资金记录数量。
3. 在本地窗口点击「开始三专家会审」。原页面自动收到本次进展和结构化结果；账号凭据、CSRF、其他研究历史不会回传。
4. 若窗口通道不可用，在观市导出 JSON，点击本圆桌左侧 **「观市看盘接入」**，在新页导入数据包。该方式可独立完成本地会审与报告导出。

固定接入页：[http://127.0.0.1:4317/market-lens.html](http://127.0.0.1:4317/market-lens.html)。接收资料不会自动开始模型调用。普通研究工作台及自定义三专家配置继续保留；它们与观市固定三席配置分别生效。云端观市负责看盘和显示结果，本地 Codex 负责模型调用，云端不使用你的 ChatGPT 登录凭据提供模型服务。

**从旧版升级：**先在原终端按 `Ctrl+C` 停止程序；保留原项目的整个 `.local` 目录。将新包解压到一个新目录，把旧 `.local` 复制到新项目同一位置，再在新目录执行 `npm ci`、`npm start`。原账号、研究记录和自定义配置可继续使用；不要把 `.local` 上传或打入分享包。首次用户按下方「启动」操作即可。

本次协议校验的可运行命令：`node --test tests/market-lens-protocol.test.mjs`。真实输入为仓库内明确标记的合成协议夹具；本轮实际输出为 **5 tests / 5 pass / 0 fail**，检查来源和通道限制、数据保真、混合标的拒绝和凭据字段隔离。运行前后不改变账号或研究记录。用户账号登录、真实模型生成和浏览器联调不由这五项测试证明。

## 原有研究工作台

已包含 2026-10-19 的协议修复：解决已登录后出现 `askForApproval.granular requires experimentalApi capability` 的错误，启用所需 capability，保留只读、工具禁用及审批拒绝规则。

输入研究问题与自己的 `.txt` / `.md` 材料，由基本面、量化、风控三个角色独立分析，再由主持人整理共识、分歧和证据缺口。可以修改并保存三位专家的方法说明、查看讨论过程与历史记录、导出 Markdown 研究报告。

本版是**可连接真实 Codex 模型的本地讨论工作流**。普通研究入口只依据你提交的文字材料；观市接入页补充冻结行情与已加载的方法资料。程序不独立查询实时行情、外部搜索、计算核验或执行交易，也未训练模型权重。三个专家使用同一个选定模型，角色不同不意味着独立事实来源。

## 启动

准备 Node.js **22.16.0 或更高版本**（含 npm）、可访问 npm 软件源及 OpenAI 登录/模型服务的网络、可使用 Codex 的 ChatGPT 账号。本项目固定使用 `@openai/codex@0.163.0`，不需要填写 API Key。

解压后，在项目目录打开终端。推荐直接运行启动脚本：

| 系统 | 可复制命令 | 作用与实际输入 | 输出及前后变化 |
| --- | --- | --- | --- |
| Windows PowerShell | `powershell -File .\start.ps1` | 读取本目录锁文件；检查本机 Node/npm；缺少依赖时执行 `npm ci` | 成功后显示本地地址；首次新增 `node_modules`，启动新增 `.local`。脚本未在你的 Windows 电脑执行 |
| macOS / Linux | `bash start.sh` | 与 Windows 脚本相同 | 成功后显示本地地址；源码不变。你的本机执行结果以终端为准 |

若 Windows 的现有策略不允许运行 PowerShell 脚本，在命令提示符中逐行运行以下手动方式，无需修改系统执行策略：

```text
npm ci
npm start
```

作用：第一条严格按 `package-lock.json` 安装依赖，第二条启动服务器。真实输入是当前源码和锁文件，不是金融样本。正常启动时会显示 `专家圆桌： http://127.0.0.1:4317`；这行是成功时的输出格式，不是你的电脑已经启动的证据。安装改变 `node_modules`，启动创建或读取 `.local`，材料原件保持不变。

打开 [http://127.0.0.1:4317](http://127.0.0.1:4317)。终端需保持运行，按 `Ctrl+C` 停止。

源码 ZIP 不含 `node_modules`、`.local` 或账号凭据，因此**首次安装需要联网**。本项目没有将你的账号或真实研究记录预装进源码包。

## 第一次使用

1. 点击 ChatGPT 登录，使用官方设备码流程；也可选择官方浏览器登录。账号认证在官方页面完成，本平台不索取账号密码或 API Key。
2. 等待界面显示已登录。**已登录不等于已验证**，模型目录中存在某个名称也不证明你的账号有权调用它。
3. 选择模型后，点击连接验证。平台发起第一轮真实生成，关闭并重启 Codex 进程，再通过 `thread/resume` 发起第二轮，核对随机校验标识是否精确返回。此操作共使用 **2 次模型调用**；两轮都成功才允许研究。
4. 输入研究问题，添加自己的 `.txt` / `.md` 内容。最多 12 份材料、合计 60,000 个字符；问题最多 6,000 个字符。资料中建议保留来源、发布日期、数据截止日、单位和口径。
5. 按需编辑三位专家的方法说明并保存，再开始讨论。每轮为三位专家各 1 次调用加主持人 1 次调用；最多 3 轮、每次研究最多 **12 次调用**。连接验证的 2 次调用另计。调用会使用账号实际可用额度，并非无限免费推理。
6. 在历史会话中查看记录或导出报告。遇到关键证据缺口会停止并列出待补资料；存在分歧才继续讨论，达到上限仍保留分歧。

当前交付没有替你登录，因此**尚未验证你账号下的真实生成、进程重启后的真实会话恢复或投资研究质量**。测试完成情况见 [验证记录](docs/validation.md)。

## 会话结果怎么读

| 状态 | 含义 |
| --- | --- |
| `completed` | 本次会审结束，未检出规定的未决分歧或证据缺口；不代表事实真实或投资判断正确 |
| `disputed` | 仍有分歧；最多讨论到设定轮数，不强求一致 |
| `needs_evidence` | 材料、引用或判断依据不足，需要补充证据 |
| `failed` | 调用、输出格式或平台运行失败；已保存的观点保留 |
| `cancelled` | 用户停止任务；已完成意见与已保存片段保留 |

材料编号检查仅核对 `E1` 等 ID 是否存在，**没有核验该材料是否真的支持主张，也没有核验外部事实**。模型自报置信度不是概率校准结果，不用于投票或强行结束讨论。

## 保存与账号边界

- 账号状态与 Codex 会话放在独立的 `.local/codex-home/`，不读取或覆盖你平时 Codex 的默认配置。凭据由官方 Codex 管理；不要分享、上传或提交整个 `.local` 目录。
- 研究记录放在 `.local/runs/*.json`，包括输入材料、模型回答和讨论结果；专家方法说明放在 `.local/experts.json`。这些文件不是加密保险箱，应使用你自己的操作系统账号和磁盘保护措施。
- 导出的报告包含输入材料，分享前检查内容。退出登录只退出本平台的独立账号，不自动删除研究记录。
- 正常退出会停止正在运行的任务。异常中断后，下次启动将未完成任务标记为中断失败，保留已有记录；当前版本不自动接续未完成研究。
- 默认仅监听 `127.0.0.1`，用于个人本机。`npm run dev` 是开发预览入口，不是公开部署方式。本应用配置只读模式、禁用工具并拒绝工具授权，但**没有对所有操作系统提供隔离保证**。

本版使用 Codex app-server 的 **managed ChatGPT 登录**：Codex 负责 OAuth、凭据保存与刷新。它不同于应用自己注册并管理授权的 **Sign in with ChatGPT（SIWC）**。官方允许现有本地/开源应用继续使用 app-server 认证，并建议迁移 SIWC；**app-server 认证不得用于商业服务或托管服务**，不能把本原型放到共享服务器为别人提供账号推理。

后续如需应用自己的 SIWC 授权，应按官方流程实现 client 注册、稳定 host ID、PKCE、令牌生命周期和用户额度展示；本项目未实现这些功能，不能只改监听地址就视为完成迁移。官方当前说明见 [Codex App Server](https://learn.chatgpt.com/docs/app-server) 和 [Sign in with ChatGPT](https://developers.openai.com/siwc/token-sharing-open-source)。

## 开发与验证

```text
npm test
npm run verify:protocol
npm run verify:local
npm run verify:capabilities
```

作用：`npm test` 检查会审、保存及服务协议；其中模型响应来自明确标记的测试替身，不是真实专家推理。`npm run verify:protocol` 使用锁定版本的真实 Codex 可执行程序，在独立未登录环境检查进程初始化、账号状态及模型目录等协议。`npm run verify:local` 连接实际 HTTP 服务与实际 Codex，检查静态页面、状态、模型目录和未登录门控；二者都不进行真实模型生成。

真实输入为本仓库测试文件和本机安装的 Codex 程序。具体实际输出、测试数量和未验证部分见 [验证记录](docs/validation.md)，不把脚本替身通过混同于真实登录或推理通过。测试运行不会给已有研究材料增添虚构财务数据。

`verify:capabilities` 从实际 `generate()` 路径取得请求参数，用真实 Codex 检查创建会话、恢复会话和发起轮次的能力门槛。它使用临时空目录；恢复和轮次请求使用不存在的线程 ID，故不会发送真实模型推理。此脚本专门覆盖本次登录后才暴露的参数错误。

代码模块、关键处理步骤及可运行检查方式见 [架构与处理链](docs/architecture.md)。
