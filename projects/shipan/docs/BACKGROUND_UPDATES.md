# 每日后台采集

2026-10-23 修复：以前只有页面触发采集；跨 Worker 请求共享的未完成 Promise 可能挂在已取消请求上。新版本保留已经完成的缓存，每次请求独立有界；后台按北京时间工作日 09:40—15:40 每小时采集一次，页面可见时仍每 60 秒刷新。后台任务是否已启用以 Sites 关联任务保存结果为准，源代码中的时刻说明本身不创建任务。

## 固定来源和写入边界

报价与价格分时、日线来自腾讯公开行情；资金分时来自东方财富，经已核实的同源延迟端点重试。标的固定为 `GET /api/refresh` 的 6 个指数和 10 只 ETF。不接受外部 URL、日期覆盖或用户提交的行情数值。写入为相同来源观测的幂等保存，源时间倒退不能覆盖较新数据。

网站维持 owner-private。后台通过 Sites `get_site` 取得当次服务令牌，仅向返回的本站地址添加 `OAI-Sites-Authorization: Bearer <token>`。令牌不进入源码、文件或任务提示；服务权限来自 Sites 网关，不假设它提供访客身份或外部连接授权。所有来源是无需账号的公开市场接口。POST 拒绝跨站 Origin；允许由网关认证、无 Origin 的后台服务调用。

## 每次运行

1. 用 Sites `get_site` 读取该关联站点、当前 URL 和服务访问权限。GET `/api/refresh` 读取当前已部署协议与固定标的。
2. POST `/api/refresh` 更新全部报价。对每个标的 POST `/api/refresh?symbol=代码&kind=index或etf`，最多 4 个标的并发，请求超时 75 秒。每个标的独立取得价格分时、日线、资金分时并等待保存。
3. 每次 POST 后 GET 相同 URL，仅读取持久记录，核对源日期、源时间与点数。HTTP 200 不是数据新鲜或保存成功的证据。
4. 首轮完成后，只对失败、保存失败或今天缺失的标的重试一次；不要循环到上游限流。休市日按实际源日保留旧值，不判断未知节假日，不补造当天数据。
5. 最后 GET `/api/refresh` 核对报价，记录仍缺失的标的及最新源日。普通运行只写数据，不编辑代码、不重新发布。任务提示可引用本已部署协议，无需开发机路径或旧会话。

## 目的、输入、调用和输出

| 处理 | 目的与实际输入 | 可运行调用 | 输出 / 前后变化 |
| --- | --- | --- | --- |
| `refreshTarget(url)` | 验证固定资产；输入 `/api/refresh?symbol=510300&kind=etf` | `refreshTarget('https://example.com/api/refresh?symbol=510300&kind=etf')` | 返回沪深300ETF配置；不匹配的 kind 抛错，不能请求任意标的 |
| `refreshSummary(payload, now)` | 区分获取时间和源日期；真实输入使用下面的部署核验 JSON | `refreshSummary(payload)` | 返回源日期、点数、保存状态；旧日即使刚取到也不算今日 |
| `GET /api/refresh` | 给新任务提供当次协议、标的和已存报价 | 通过本站服务权限请求该路径 | 只读存储，不借验证再次抓取源数据 |
| `POST /api/refresh` | 无人值守更新 16 个报价 | 使用同一认证、POST 无正文 | 等待持久写入，返回保存结果和当前日有效数 |
| `POST /api/refresh?symbol=510300&kind=etf` | 独立更新三类历史，任一来源失败不会丢弃其他成功结果 | 使用同一认证、POST 无正文 | 返回 minute / daily / flow 三份状态，之后 GET 同一路径核验 |
| 跨日后台运行 | 不依赖页面打开；时钟使用 Asia/Shanghai | 关联 Sites 后台任务 | 未取得当天源数据时保留原日与错误，不把昨天改成今天 |

可执行协议回归：`node --test tests/refresh-protocol.test.mjs`。测试使用明确合成数据，不是市场行情。
