# 这一阶段的量化系统工作总结

根据本次提供的 18 份文件整理。本文描述文件中可核验的工程能力，不将 Notebook 保存的输出视作重新验证的实证结果。

## 从行情到模型的工程链路

1. **期货数据清洗与覆盖审计**：按交易所整理日线，利用合约目录和交易日历检查缺失，处理郑商所三位年月代码的十年复用歧义。公开版改为供应商无关的数据接口，移除数据库操作和供应商账号。
2. **主次连续合约**：实现基于活跃度评分、确认天数、切换阈值和交割保护期的状态决策；保存决策日与生效日，输出主次连映射、原始行情、换月事件和调整价格。
3. **因子研究数据工程**：将标准化、分组、PCA、精确时刻采样拆成独立模块；维护列顺序、样本键和处理状态指纹。
4. **模型实验协议**：统一树模型与序列模型接口，区分 Fit/Valid 选轮数与冻结轮数后的最终重训，保存预测与模型清单，按月与合约分析指标。
5. **分组模型与融合**：扩展至时间顺序 OOF、Ridge 元模型和分层残差研究；公开版加强标签时间边界与缓存身份绑定，避免把未来标签或过期缓存混入训练。
6. **质量与复现**：检查缺失、常值、异常、序列相关性、分段特征与前缀不变性；保存随机种子、配置、代码/输入哈希和环境版本。

7. **商品期货截面多空 CTA**：以新增分板块 Notebook 为主，按板块独立训练，默认预测 30 分钟收益减板块中位数；通过固定权重排名融合形成主次力多空组合，新增边界明确的区间研究回测。来源实际使用 LightGBM 和板块内标签 z-score，公开扩展与原实现分别记录。

## 名称与口径纠正

- 最新连续合约 Notebook 的“30 天”是距最后交易日的**自然日交割保护窗**，不是 30 日滚动评分。
- 《三模型对比》虽然文件名包含 iTransformer，实际默认实验使用的是时间 token 的 **Transformer**；另一份单因子 Notebook 和模型模块提供因子 token 的 **iTransformer**。公开 API 保留两个明确不同的标识。
- 最新连续价格的比例在换约时用前一交易日已知的旧/新合约收盘价衔接，公开版函数为 `causal_ratio_adjust`；首段锚定、向前累计，不依据“后复权”三个字推断它必然利用未来信息。连续价格收益不能代替逐合约持仓及移仓成本账本。
- 一些早期原型使用同日选约、事后筛品种或样本末日推断年份。公开系统使用后续更严格的数据契约，不把旧版原型与新系统混为一谈。
- 原分层残差研究包含测试反馈参与设计的说明，因此其既有结果不能再被表述为未触碰的最终样本外检验。
