# 研究预测与后续交易回测的接入契约

本仓库已实现因子研究、数据处理、训练、融合与预测评估。用户正在开发交易回测，后续按本契约接入；本文定义输入与验收要求，**不表示当前已有成交模拟、持仓账本、资金曲线或策略损益引擎**。

## 当前预测导出

`quant-research demo/run` 成功评估后生成 `signals.csv`，不含真实未来标签：

| 字段 | 含义与接入约束 |
| --- | --- |
| `Date` | 交易日；夜盘使用经确认的交易日归属 |
| `Contract` | 研究资产 ID；明确区分股票、真实交割合约与待解析的连续角色 |
| `Datetime` | 预测信息截止时刻，使用配置声明的时区 |
| `prediction` | 模型数值输出，量纲由目标定义决定，不自动等于仓位或手数 |
| `signal_available_at` | 当前等于 Datetime，是零推理/传输延迟的研究假设 |
| `model` | 模型标识；明确选取模型或事先冻结组合规则 |
| `target_name` | 目标名称；完整公式、期限、价格基准需另行登记 |
| `synthetic` | 为 true 时仅用于软件验收 |

按模型和完整样本键检查重复，以运行清单中的内容哈希绑定信号文件。接入还需登记运行标识、模型训练截止、标签定义、配置版本与资产类别，不从字符串或包名猜测资产类型。

当前 `signal_available_at` 没有模拟特征计算、推理、通信和下单延迟，不能直接当作真实可成交证据。实际可得时刻必须不早于特征最晚可得时刻、模型就绪时刻与 Datetime，并增加明确的计算和传输延迟。

收盘后计算的信号不能成交在同一根 bar 的开盘价或已发生的盘中极值。使用同一时间戳的收盘价也需交易机制与截止时间证据，不能仅凭时间戳相等宣称可成交。

## 真实合约映射

`ContinuousResult.mapping` 提供 `product, role, date, decision_date, contract_id`、前任身份、切换原因和确认记录。`date` 为生效交易日，T 收盘决策下一明确交易日生效。

若预测 Contract 已为真实合约完整身份，按其获取报价及合约元数据。若代表“品种主力/次主力”，需按角色和生效日映射为真实合约。日级映射不能代替订单时刻；下游还需定义映射完成、执行时刻及夜盘归属。

保留原价、合约乘数、币种、最小变动单位及其历史版本。换约分别平旧和开新，按两笔真实成交及费用记账。原价跳变和因果复权涨跌均不能直接充当移仓损益。不得用造平 bar、未来桥接价格或没有成交的复权价格产生成交记录。

## 回测方需要提供

| 输入或规则 | 必须明确的内容 |
| --- | --- |
| 信号到仓位 | 阈值、组合权重、仓位上限、调仓频率与参数冻结时点 |
| 可交易资产池 | 当时已知的上市/退市、停牌、涨跌停、交割限制及合约资格 |
| 日历和报价 | 时区、夜盘、报价可用时间、缺失处理、撮合及不成交规则 |
| 执行与成本 | 下单时刻、价格基准、手续费、点差、滑点、容量与市场冲击 |
| 资金与风险 | 乘数、保证金、现金、杠杆、强平、风险限额、公司行动 |
| 持仓与移仓 | 逐资产/真实合约持仓、旧新分别成交、交割前退出 |
| 结果来源 | 输入哈希、代码、配置、种子、环境与事件日志 |

股票的停牌、退市、除权和可交易数量约束，与期货保证金、到期及移仓规则分别实现；共享 Contract 字段不代表执行规则相同。

## 接入验收

1. 固定输入、配置和环境后，信号、订单、成交、持仓及现金变化可以逐项追踪。
2. 扰动未来行情、标签与元数据，不改变此前信号、订单和持仓；验证真实时点边界，而不只检查排序。
3. 构造标签跨界、换约、缺行情、停牌/涨跌停、非交易日和到期场景，不制造不可成交收益。
4. 区分毛收益、净收益，费用和移仓可逐项核对，标记未建模的成本与容量限制。
5. 根据 Test 研究过的交易规则需新的未查看区间；模型测试独立不自动保证下游策略独立。

这些是后续回测模块的验收要求，当前预测评估没有隐含承诺已满足它们。
